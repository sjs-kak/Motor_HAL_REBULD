## 4. 当前卡点：四轮不停（最重要）

### 4.1 现象

调试运行自动动作（`CFG_DEBUG_AUTOTEST`）或 `Motion_Drive(1200, 0)` 后，S 曲线走完、
3 秒看门狗到点、软件侧确实执行了停车，但**轮子继续以约 1200 Hz 转，不停止**。

### 4.2 已取证的数据（都可复现）

| 观测量 | 值 | 说明 |
|---|---|---|
| `s_speed_left` / `s_speed_right` | `0` / `0` | 软件认为已停 |
| `s_alive_ms` | `0` | 看门狗已停车 |
| `uwTick` | 正常递增 | 系统没死 |
| `TIM1->CR1`（0x40010000） | `0x81` | **CEN=1，定时器仍在跑** |
| `TIM2->CR1`（0x40010004） | `0x81` | 同上 |
| `TIM1/TIM2->ARR` | `0x63` = 99 | = `CFG_PUL_ARR`，确认是脉冲定时器 |
| `TIM1/TIM2->PSC` | `0x577` / `0x2BB` | 1399 / 699 → 1200 Hz（两侧都是 1200 Hz） |
| `s_start_cnt` | 135 | 与 1.2 s / 8 ms 采样的 S 曲线相符（约 150 个采样点），说明只跑过一次斜坡 |
| `s_stop_cnt` | 8 | 4 次“速度归零”事件 × 2 通道 |
| `s_forced_cnt` | 先 `0`，后 `5075636` | 见下 |

### 4.3 已经查明的一个真实 bug（已修）

`s_forced_cnt = 0` 不是“定时器没在跑”，而是**安全网根本执行不到**：

```c
/* 旧代码：看门狗停车会把 s_alive_ms 清零，于是每圈都在第一行返回 */
if (s_alive_ms == 0) return;                       /* ← 总是从这里返回 */
if (速度都是 0) { EnsureStopped(); return; }        /* ← 永远执行不到 */
```

修正后（`App/Src/motion.c:227`）安全网提到最前，`s_forced_cnt` 随即涨到 **5075636**——
说明它每圈都在清 `CEN`，但**同一圈里又有东西把 `CEN` 置回 1**。目前仍未找到这个“别人”。

### 4.4 已排除的假设

- 固件外设配置：`BRR=0x2D9`（115200 @84 MHz APB2，正确）、`GPIOA MODER` 中 PA9/PA10 为 AF、
  `CR1=0x202C`（UE/TE/RE/RXNEIE 全开）、`NVIC ISER1=0x00400020`（IRQ37 已使能）、
  `PRIMASK=BASEPRI=0`、向量表 `0x080000D4 → 0x080052D5`（`USART1_IRQHandler`，非默认桩）。
- 启动/时钟：`RCC->CR=0x03037983`，HSE、PLL 全部就绪。
- `Motion_Move()` 内部的 `StartAll → SetFreq` 顺序（`motion.c:167-172`）确实是先启动再设置。
- `App_Rc_Tick()` 明确不调用任何 `Motion_*`（`App/Src/app_rc.c` 注释与实现一致）。
- 全工程搜索：`StartAll` 唯一调用点在 `motion.c:170`；`HAL_TIM_PWM_Start` 唯一调用点在
  `Bsp_MotorPulse_Init()`（`motion.c:138`，只在 `Motion_Init()` 里）。

### 4.5 已加的两层兜底（**尚未实测**）

```c
void Bsp_MotorPulse_EnsureStopped(void)     /* Bsp/Src/bsp_motor_pulse.c */
{
    if (TIM1->CR1 & TIM_CR1_CEN) { s_forced_cnt++; TIM1->CR1 &= ~TIM_CR1_CEN; }
    if (TIM2->CR1 & TIM_CR1_CEN) { s_forced_cnt++; TIM2->CR1 &= ~TIM_CR1_CEN; }
    __HAL_TIM_MOE_DISABLE(BOARD_HTIM_LEFT);   /* 第二层：不依赖 CEN */
}
```

`MOE`（`BDTR` 主输出使能）为 0 时，**无论 CEN / CCR / CCER 如何，TIM1 的输出引脚都被硬件
强制无效**。`StartAll()` 里已补 `__HAL_TIM_MOE_ENABLE()`。

## 6. 调试器速查（今天的教训沉淀）

### 6.1 console 语法（重要）

VS Code 调试控制台里 `-exec call Fn()` **一定失败**（扩展要求 `frameId`），正确写法是：

```
>-interpreter-exec console "call Motion_Drive(1200, 0)"
>-interpreter-exec console "print s_alive_ms"
>-interpreter-exec console "print/x *(unsigned int*)0x40010000"
```

- `>` = 解释器命令，`>-` = 原始 MI 命令；`-exec` 是 cortex-debug 的习惯，这个扩展不认。
- **每次 `call` 都会让之前选的栈帧句柄失效**（重绘堆栈后 `$1/$2` 会变），
  报 `Evaluation of expression without frameId` 时**重新点一下调用栈里的帧**再执行。
- 不要在 `HAL_Init()` 之前 `call` 运动函数：`Osal_GetTickMs()` 依赖 SysTick，
  未初始化时会死循环，表现为“车不动 + 调试控制台挂住”。
- 调试过程中**不要按板子上的复位键**：会与 GDB 失步（`target was not halted…`）。


## 9. 不要做的事（今天踩过的坑）

- 不要在看门狗仍在工作时用 `Motion_Drive(x, 0)` 长时间空转做实验——它不受看门狗约束
  （`holdMs=0` 表示“到位即返回、保持速度”，靠下一条命令或急停收尾）。
- 不要在 `HAL_Init()` 之前 `call` 任何依赖 `HAL_GetTick` 的函数（会死循环）。
- 不要在调试会话中按板子复位键（GDB 会失步）。
- 不要把未命名的 getter 当调试接口：`-Wl,--gc-sections` 会把没有调用者的函数整段删掉，
  必须真的在别处被调用（`?` 命令输出就是一例）。
